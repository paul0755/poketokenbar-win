# PokeTokenBar for Windows — 0.1.0 리포트

작성 2026-09-16

AI 코딩 도구에 쓴 토큰으로 포켓몬을 키우는 Windows 트레이 앱.
macOS 전용인 [chattymin/PokeTokenBar](https://github.com/chattymin/PokeTokenBar)(MIT)의
아이디어를 Windows로 옮겼습니다. **코드를 이식한 게 아니라 새로 만들었습니다.**

---

## 1. 왜 새로 만들었나

원본은 Swift/SwiftUI입니다. Windows에는 SwiftUI가 없어서 **UI 레이어를 통째로 다시 써야** 합니다.

이미 시도한 사람이 있었습니다. PR [#114](https://github.com/chattymin/PokeTokenBar/pull/114)는
Win32/GDI로 포팅한 완성품(+287,181 / −123, 60개 파일)이었지만 머지되지 않았습니다.
메인테이너의 답은 이랬습니다.

> 솔로 메인테이너로서 직접 쓰지도 않는 플랫폼의 Win32/GDI 구현을 하나 더 떠안을 수 없다

**코드가 나빠서가 아니라 유지보수 부담** 때문이었습니다. 대신 별도 레포나
Tauri/Compose로의 전면 이전은 받아들이겠다고 했습니다.

### 스택 선택

| 후보 | 판단 |
|---|---|
| Swift 브랜치 빌드 | VS Build Tools 7GB + Swift 툴체인. 브랜치가 2개월 묵음 |
| Tauri | Rust MSVC 링커 때문에 **똑같이 VS Build Tools 7GB** 필요 |
| **Electron** | **Node만 있으면 됨.** 선택 |

설치에 반나절을 쓰는 대신 코드를 쓰기로 했습니다.

## 3. 기능

### 토큰 집계

| 도구 | 경로 | 상태 |
|---|---|---|
| Claude Code | `~/.claude/projects/**/*.jsonl` | ✅ |
| Codex | `~/.codex/sessions/**/*.jsonl` | ✅ |
| Gemini | — | ❌ Antigravity 로그·SQLite에 토큰이 없음 |
| Copilot | — | ❌ `.copilot` 전체에 토큰 필드 없음 |

입력 · 출력 · 캐시 쓰기 · 캐시 읽기로 나눠 셉니다.
일 / 주(달력) / 월 / 5시간 창 / 롤링 7일 집계.

### 게임

- **221개 진화 라인** (1~5세대), 5단계: 알 → 부화 → 1차 → 최종 → 마스터
- **개체별 성장** — 받은 시점부터 쓴 토큰으로만 자람
- **포획률 기반 가중 뽑기** — ★1~5, 공식 포획률을 5등급으로 압축
- **성격 25종**, **이로치** 1/128 (부적 1/64)
- **이상한사탕** — 25M당 1개, 졸업 시 +5
- **상점** — 알 3종 · 민트 · 반짝이는 부적
- **도감** — 221칸, 등급별 수집 현황
- **난이도** — 성장 속도 / 상점 가격 각 10~200%

### 화면

- **메인 창** — 홈 / 상점 / 도감 탭
- **바탕화면 펫** — 투명 창, 배회, 드래그, 클릭하면 메인 창
- **알림** — 진화 · 졸업 · 한도 임박
- **설정** — 난이도 · 알림 · 펫 · 갱신 주기 · 자동 시작
- **인스톨러** — NSIS, 관리자 권한 불필요

## 4. 설계에서 갈린 지점들

### macOS와 다를 수밖에 없었던 것

| | macOS | Windows |
|---|---|---|
| 숫자 표시 | 메뉴바에 **글자로** | 트레이는 아이콘만 → **툴팁 + 창** |
| 애니메이션 | 메뉴바에서 재생 | `nativeImage`가 GIF를 못 움직임 → 트레이는 PNG, 화면은 GIF |
| 펫 드래그 | AppKit | `app-region: drag`를 쓰면 클릭 이벤트가 안 옴 → **직접 구현** |

### 스스로 정한 원칙

**없는 값을 지어내지 않는다.**
Gemini·Copilot을 넣지 않은 것도, 5시간 창에 %를 안 띄우는 것도 같은 이유입니다.
한도값이 로컬에 없으면 퍼센트는 추정이고, 추정을 사실처럼 보여주면
그 순간부터 모든 숫자를 못 믿게 됩니다. Codex 주간 %만 보여주는 건
opencodex가 캐시한 **실제 쿼터**가 있기 때문입니다.

**손으로 적으면 반드시 틀린다.**
221개 라인의 도감 번호와 한국어 이름을 처음엔 기억으로 적었고, 실제로 틀렸습니다
("차임리" → "치렁"). PokéAPI에서 받아 생성하는 스크립트로 바꿨습니다.

**조용히 실패하지 않게 한다.**
`catch {}`로 삼킨 오류가 이 프로젝트에서 가장 오래 걸린 버그들의 원인이었습니다.

## 5. 개발 과정에서 겪은 것

### 숫자가 1.8배 부풀려져 있었다

Codex를 붙이면서 드러났습니다. Claude Code는 **하나의 API 응답이 여러 레코드로
쪼개져** 기록되는데(텍스트 블록 + tool_use 블록), 각 레코드가 **같은 `usage`를
그대로 복사**해서 들고 있습니다. 그걸 전부 더하고 있었습니다.

중복 그룹 536개를 확인했더니 토큰 값이 예외 없이 동일했습니다.
`requestId` 기준으로 1건만 세도록 고쳤습니다. **709M → 390M.**

Codex에도 같은 함정이 있었습니다. `total_token_usage`라는 편한 누적값이
흐르는데, 재개된 세션이 이전 누계를 이어받습니다 — 실제로 한 세션이
**410M에서 시작**했습니다. 레코드 단위 합산이 맞다는 건 두 세션에서
Codex 자체 누계와 **0.0% 일치**로 확인했습니다.

### 조용히 죽는 것들

| 증상 | 원인 |
|---|---|
| 팝오버가 "불러오는 중"에서 멈춤 | 역슬래시 하나가 사라져 정규식이 안 닫힘 → **스크립트 전체 파싱 실패**. 렌더러 오류는 메인 stdout에 안 나와서 `console-message`를 끌어오고서야 보였다 |
| 설정이 통째로 기본값이 됨 | `save.json`에 BOM. `JSON.parse`가 터지는데 `catch`가 삼킴 |
| 도감 버튼이 안 눌림 | `id="dex"`가 둘. `getElementById`가 앞의 div를 반환해 핸들러가 엉뚱한 데 붙음. **오류도 안 남** |
| 펫이 2px 가다 멈춤 | `setPosition`이 부른 `moved` 이벤트가 OS 루프를 거쳐 늦게 도착 → 우리 이동을 "사용자 드래그"로 오인 |
| 키우던 포켓몬이 사라짐 | 인스톨러용 `productName`을 넣자 Electron의 userData 경로가 바뀜 |

### 스스로 만든 설계 실수

- **무제한 리롤** — 희귀도를 만들어놓고 뽑기를 공짜 버튼으로 뒀습니다.
  ★5가 1/739여도 1초에 한 번 누르면 10분이면 나옵니다. 사탕을 화폐로 도입.
- **누적 토큰으로 성장 계산** — 뭘 뽑든 즉시 최종 진화. 키우는 게임인데
  키우는 과정이 없었습니다. 개체별 `bornAt` 도입.
- **성장 속도가 이름과 반대** — 200%가 "두 배 빨리"가 아니라 "두 배 더 써야"였습니다.
  배수를 임계값에 곱한 게 원인. 성장량에 곱하는 쪽이 맞습니다.
- **도감이 최종 진화 모습만** — 파비코를 키우는데 도감엔 파비코리로 떴습니다.
- **보유가 아닌 아이도 펫으로** — 도감은 "만난 기록"이지 보유가 아닙니다.

## 6. 알려진 문제 (0.1.0 시점)

0.1.1에서 1~5를 고쳤습니다. 6~8은 설계 변경이라 다음 계획에 있습니다.

| # | 증상 | 진단 |
|---|---|---|
| 1 | 설정에서 펫 크기를 바꾸면 펫이 사라짐 | 투명 창은 `setSize`로 잘 안 바뀜. 크기 변경 후 화면 밖으로 나갈 수 있는데 위치를 다시 잡지 않음 |
| 2 | "숨기기" 버튼이 토글되지 않음 | `togglePet()`이 `refresh()`를 안 불러 stats가 다시 안 감. **확인됨** |
| 3 | 월별 차트 클릭이 안 먹음 | 클릭 핸들러가 없음. `title` 툴팁만 있음 |
| 4 | Claude 주간 사용량을 알 수 없음 | 공식 쿼터가 로컬에 없음. 다만 **롤링 7일 도구별 수치는 이미 계산됨** (Claude 497M) — 화면에 안 내보내고 있을 뿐 |
| 5 | 30초 갱신이 안 되는 것 같음 | 폴링 자체는 도는 것을 확인. 화면 갱신 경로를 더 봐야 함 |
| 6 | 알을 사면 키우던 포켓몬이 사라짐 | 의도한 동작이지만 납득이 안 됨. 여러 마리 보유(박스)로 바꿔야 함 |
| 7 | 펫을 한 마리만 띄울 수 있음 | 창을 여러 개 띄우는 구조로 확장 필요 |
| 8 | 사탕이 화폐로만 쓰임 | 성장 가속(경험치) 용도 추가 필요 |

## 7. 다음 계획

### 우선순위 1 — 보유 구조 바꾸기 (문제 6·7·8)

지금은 한 마리만 키우고, 알을 사면 이전 아이가 사라집니다.

- **박스** — 여러 마리를 보유하고 그중 하나를 "키우는 중"으로 지정
- **펫 여러 마리** — 보유한 아이들을 동시에 바탕화면에
- **사탕으로 성장 가속** — 화폐이자 경험치. 원본의 이상한사탕과 같은 개념

### 우선순위 2 — 개체별 프로필

도감에서 종을 열면 그 개체의 상세를 봅니다.

- 레벨 · 성별 · 성격 · 특성 · 개체값 · 계산된 능력치 · 배운 기술
- 종 설명과 특성·기술은 선택 언어로. **PokéAPI에 번역이 없으면 영어로**
- PokéAPI의 `pokemon`, `ability`, `move`, `stat` 엔드포인트에서 생성

### 우선순위 3 — 버그 수정 (문제 1~5)

### 하지 않기로 한 것

- **$ 비용 계산** — 단가표를 계속 따라가야 해서 유지보수가 큼
- **다국어** — 지금은 한국어만
- **코드 서명** — 인증서 비용
